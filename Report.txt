# 🗂️ Destiny Draw – Reporte Completo del Proyecto
**Versión:** Febrero 2026  
**Base:** Análisis sobre código fuente real (todos los módulos)

===============================================================================

## 1. Descripción General

Destiny Draw es una SPA (Single Page Application) sin servidor para jugadores de Yu-Gi-Oh!. Funciona 100% desde el navegador. Usa localStorage para toda la persistencia y se conecta a la API pública de YGOProDeck para datos de cartas. La arquitectura es modular: cada módulo es un objeto JavaScript global independiente.

### `navigation.js`
Controla el sistema de pestañas. Muestra/oculta las secciones `<section id="X-content">` y activa/desactiva los botones del nav. Al cambiar de pestaña notifica a Estadísticas para mostrar/ocultar el widget flotante.

| Función | Descripción |
|---|---|
| `init()` | Registra listeners en todos `.nav-button` y carga pestaña inicial (`buscador`) |
| `showTab(tabName)` | Oculta todo, muestra la sección indicada, activa botón, llama a `Estadisticas.updateFloatingWidgetVisibility()` |
| `previousTab()` / `nextTab()` | Navegación circular entre pestañas |
| `getCurrentTab()` | Devuelve la pestaña activa actual |

**Pestañas disponibles:** `buscador`, `mideck`, `estadisticas`, `simuladores`, `meta`, `formacion`, `config`

**Objeto Shortcuts** (incluido en el mismo archivo):  
Botón flotante ⚡ que abre un menú de accesos rápidos configurables. Lee los shortcuts desde `ConfigManager.getShortcuts()`. Cada shortcut tiene: tab destino, ID de sección a la que hacer scroll, y módulo a refrescar (Winrate, Duelista, Estadísticas). El catálogo completo cubre: Buscador, Decks Guardados, Mi Deck Notas, Análisis vs Meta, Internal Score, Winrate, Top Tier, Decks del Meta, Poder de Cartas, Counter-Cards, Exportar Datos, Nivel Duelista, Roles, Mecánicas y Counters, Staples, Nomenclatura, Pilares.

### `stats.js`
Motor de cálculo de puntuaciones. No tiene UI propia — provee los números a Estadísticas y Deck.

| Función | Descripción |
|---|---|
| `calculateInternalScore(cards)` | Calcula Consistencia, Potencia, Resiliencia (0–10) por roles asignados |
| `calculateExternalScore(cards, powerCache)` | Vulnerabilidad del deck vs cartas del meta que counteren sus mecánicas |
| `calculateCounterDeckScore(cards)` | Capacidad de interrupción del deck al meta, con penalización por bricks |
| `calculateDiminishingReturns(roleName, count)` | Penaliza sobrecargar un rol según umbrales del Config |

**Detalles de `calculateInternalScore`:**
- Normaliza variantes de nombre de rol a forma canónica (ej. "Boss", "carta jefe", "ace monster" → mismo rol)
- Pilares: Consistencia (searcher, starter), Potencia (boss monster, boardbreaker, booster, removal, disruption), Resiliencia (negator, extender, recycle, undestroyable, untargetable, unaffectable)
- Cartas con restricción "once per turn" o "per duel": copias adicionales cuentan al 50%
- Penalización por deck > 43 cartas: -0.5 por cada carta extra
- Cada pilar se escala (×15 consistencia, ×20 potencia, ×18 resiliencia) y se limita a 10
- Ponderación final: 33% cada pilar

### `estadisticas.js`
Módulo de visualización del análisis completo. Es el módulo más extenso de la app.

**Secciones que renderiza:**

| Sección (ID) | Contenido |
|---|---|
| `deck-analysis-sec` | Análisis vs Meta: Internal/External/Counter-Deck Score, mecánicas detectadas, cartas amenaza, decks amenazantes, staples faltantes |
| `deck-stats-sec` | Internal Score con barras por pilar |
| `top-tier-sec` | Decks del meta ordenados por presencia de cartas clave |
| `meta-decks-sec` | Lista de decks del meta importados con filtro por carpeta (multi-selección) |
| `power-scores-sec` | Power Score de cada carta del meta |
| `counter-cards-sec` | Cartas del meta con función de interrupción activa |
| `winrate-sec` | Widget de Winrate (renderizado por `Winrate.renderSection()`) |
| `duelista-sec` | Perfil del Duelista (renderizado por `Duelista.renderSection()`) |
| `export-sec` | Descarga reportes .txt y .csv |

**Funciones clave:**

| Función | Descripción |
|---|---|
| `createFolder()` / `deleteFolder()` | Gestión de carpetas de meta por fecha de formato |
| `importYDK()` / `processYDKFile()` / `parseYDK()` | Importa archivos .ydk al meta, resuelve IDs via API |
| `updateDeckStats()` | Recalcula todos los scores y actualiza la UI |
| `renderDeckAnalysis()` | Renderiza la sección de análisis vs meta |
| `calculatePowerScore()` | Para cada carta del meta: presencia + specBonus + counterBonus |
| `renderPowerScore()` / `renderCardRecurrence()` / `renderCounterCards()` | Renderizado de tablas del meta |
| `createDeckFloatingWidget()` / `updateFloatingWidget()` | Widget flotante con scores en tiempo real, visible en otras pestañas |
| `updateFloatingWidgetVisibility(tabName)` | Muestra/oculta el widget según la pestaña activa |
| `toggleFolderFilter(folderName)` | Activa/desactiva filtro de carpeta (multi-selección) en la lista de meta |

**Lógica de External Score:**
El denominador es la suma de todos los counterBonus del meta activo (escala relativa al formato). El score es inversamente proporcional a la amenaza total: `(1 - amenaza/baseline) × 10`.

**Lógica de Counter-Deck Score:**
Suma counterBonus × copias de cartas counter del deck. Las cartas "Brick" no suman sino que se acumulan para aplicar una penalización proporcional: `penalización = rawCounter × (bricks/total) × 0.6`.

**Lógica de Power Score del meta:**
Presencia (% de decks que la incluyen) + specBonus (mecánicas detectadas × presencia) + counterBonus (counters detectados × presencia). Las cartas con counterBonus > 0 se marcan como `isCounter: true` y alimentan el External Score.

**Probabilidad de Encuentro:** usa distribución hipergeométrica para calcular P(ver al menos 1 copia en mano inicial del oponente), ajustada por presencia del deck en el meta.

### `config.js`
Interfaz visual de configuración. Todo guarda vía ConfigManager.

**Secciones:**
- **Roles** (`#roles-section`): crear/editar/eliminar roles. Cada rol tiene: nombre, keywords de detección, conditionals, scope de nomenclatura, peso (0.1–2.0)
- **Especialidades y Counters** (`#specialties-section`): pares mecanicRole ↔ counterRole, cada uno con lista de keywords
- **Staples** (`#staples-section`): cartas consideradas esenciales en el formato actual. Se pueden marcar/desmarcar también desde el CardViewer
- **Nomenclatura** (`#nomenclature-section`): categorías con nombre, color, y condiciones de matching (startsWith, contains, notContains, endsWith — todos como arrays, lógica OR dentro de cada campo)
- **Rendimientos Decrecientes** (`#pillars-section`): umbrales por rol que afectan el Internal Score

### `nomenclature-analyzer.js`
Analiza el texto del efecto de una carta contra las categorías configuradas.

| Función | Descripción |
|---|---|
| `analyzeCard(card)` | Itera categorías, divide el efecto con el delimiter de cada una, detecta categoría por segmento |
| `detectCategory(paragraph, categories)` | Evalúa condiciones startsWith/contains/notContains/endsWith |
| `matchesConditions(paragraph, conditions)` | Lógica de matching: OR dentro de cada campo, AND entre campos |
| `splitIntoParagraphs(text, delimiter)` | Divide texto con el delimiter provisto. Si no hay delimiter, devuelve el texto como bloque único |
| `_getCategoryDelimiter(cat)` | Infiere el delimiter de la categoría desde su `endsWith`. Devuelve regex que divide conservando el delimitador al final del segmento |
| `getSummary(analysis)` | Resumen de categorías presentes en el análisis |

**Comportamiento actual del splitting:** cada categoría define su propio delimiter basado en su campo `endsWith`. Si una categoría no tiene `endsWith`, el efecto se evalúa como bloque completo. Las cartas se analizan categoría por categoría y un segmento no se reclasifica una vez asignado.

### `specialty-analyzer.js`
Detecta mecánicas (especializaciones) y counters de cartas/decks, basado en roles — no en keywords propias.

| Función | Descripción |
|---|---|
| `_detectRoles(card)` | Detección interna de roles desde descripción (excluye monstruos normales). Replica la lógica de `deck.autoAssignRoles` sin depender del módulo Deck |
| `analyzeCard(card)` | Usa roles pre-asignados de la carta o los detecta internamente. Cruza contra pares de Especialidades/Counters del Config |
| `analyzeDeck(cards)` | Acumula especializaciones y counters de todo el deck (solo main + extra) |
| `getPrimarySpecialization(deckAnalysis)` | La mecánica con mayor cantidad de cartas en el deck |
| `renderDeckSpecializations(deckAnalysis)` | HTML con lista de especializaciones ordenadas por frecuencia |

**Cómo funciona la detección:** compara los roles de la carta (en minúsculas) contra `pair.mechanicRole` y `pair.counterRole` de cada par configurado. Si coincide con `mechanicRole` → es una especialización; si coincide con `counterRole` → es un counter.

## 5. Bugs Conocidos Activos

---

### 🔴 Bug 1 — `navigation.js` + `index.html` — doble disparo de `showTab`

**Problema:** Los botones del nav (Buscador, Mi Deck, Estadísticas, Simuladores, Meta, Formación) tienen `onclick="switchTab('...')"` en el HTML y además `navigation.js` les agrega un `addEventListener('click', ...)` en `init()`. Cada clic ejecuta `showTab` dos veces.

**Fix:** Eliminar los atributos `onclick="switchTab('...')"` de todos los `<button class="nav-button">` en `index.html`. Dejar solo los listeners del módulo. El botón Config no tiene `onclick` y ya funciona bien — es el modelo correcto.

---

### 🔴 Bug 2 — `stats.js` — typo `undestroyeble` en pilares de Resiliencia

**Problema:** En la lista de roles que aportan a Resiliencia, el sistema usa `'undestroyeble'` (con e) en lugar de `'undestroyable'`. El rol real en el sistema se llama `undestroyable`. Resultado: cartas marcadas con ese rol no suman nada al pilar de Resiliencia del Internal Score.

**Fix:** Corregir el typo en la constante/array de roles de Resiliencia dentro de `stats.js`. Buscar `undestroyeble` y reemplazar por `undestroyable`.

---

### 🟡 Bug 3 — `specialty-analyzer.js` — `cardCountersCard` retorna siempre 0

**Problema:** La función `cardCountersCard()` existe en el módulo pero su implementación es `return 0` — está vacía. Cualquier lógica que llame a esta función para saber si una carta countera a otra siempre obtendrá 0.

**Estado:** Impacto bajo si el flujo principal no la usa directamente, pero es una función declarada y sin implementar.
