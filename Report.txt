INFORMACIÓN GENERAL DEL PROYECTO
--------------------------------------------------------------------------------
Nombre: Destiny Draw - Yu-Gi-Oh! App
Plataforma: Web (HTML5, CSS3, JavaScript)

Inicio del Proyecto: 07/02/2025
Última Actualización: 07/02/2025 (Etapa 1 completada + Módulo Buscador)

OBJETIVO DEL PROYECTO
--------------------------------------------------------------------------------
Crear una aplicación web llamada "Destiny Draw" funcional y sencilla para 
gestionar mazos (decks) de Yu-Gi-Oh!, con capacidades de búsqueda de cartas, 
análisis estadístico, simuladores, información del meta actual, recursos de 
formación y configuración personalizable.

La aplicación está diseñada con arquitectura modular para facilitar el
mantenimiento y escalabilidad futura.

PALETA DE COLORES PRINCIPAL
--------------------------------------------------------------------------------
Color Base: #003366 (Azul marino oscuro)
El esquema de colores está diseñado alrededor de este tono azul profundo,
que da una sensación profesional y relacionada con el tema de Yu-Gi-Oh!.

COMPONENTES PRINCIPALES IMPLEMENTADOS
--------------------------------------------------------------------------------

1. HEADER CON EFECTO PARALLAX
   - Diseño visual atractivo con fondo parallax
   - Logo centrado (placeholder para imagen)
   - Altura: 250px (180px en móvil, 150px en pantallas pequeñas)

   Razón de implementación:
   - Crear una identidad visual fuerte para la aplicación
   - Efecto parallax mejora la experiencia visual sin afectar rendimiento
   - El diseño es responsive y se adapta a diferentes tamaños de pantalla

2. MENÚ DE NAVEGACIÓN CON PESTAÑAS
   - 7 pestañas principales: Buscador, Mi Deck, Estadísticas, Simuladores,
     Meta, Formación, Config
   - Navegación sticky (se queda fija al hacer scroll)
   - Scroll horizontal en móviles para todas las pestañas
   - Indicador visual de pestaña activa con borde inferior
   - Efecto hover con gradiente animado
   
   Razón de implementación:
   - Organización clara de funcionalidades
   - Sticky navigation mejora UX al permitir cambiar de sección sin scroll
   - Los efectos visuales proporcionan feedback claro al usuario

3. ÁREA DE CONTENIDO PRINCIPAL
   - Sistema de pestañas con transiciones suaves
   - Solo una pestaña visible a la vez
   - Animación fadeIn al cambiar de pestaña
   - Contenedor con max-width para legibilidad en pantallas grandes
   
   Razón de implementación:
   - Separación lógica de funcionalidades
   - Las transiciones mejoran la percepción de fluidez
   - Max-width evita líneas de texto demasiado largas en PC

4. BOTÓN FLOTANTE "SCROLL TO TOP"
   - Ubicación: Esquina inferior derecha
   - Se muestra solo después de 300px de scroll
   - Animación smooth al hacer click
   - Diseño circular con gradiente
   - Efecto hover con elevación
   
   Razón de implementación:
   - Mejora la navegación en páginas con mucho contenido
   - Threshold de 300px evita que aparezca innecesariamente
   - Posición fija no interfiere con el contenido principal


MÓDULOS JAVASCRIPT IMPLEMENTADOS
--------------------------------------------------------------------------------

1. LOGGER.JS - Sistema de Logging
   ✓ Registro completo de eventos, funciones y acciones
   ✓ Múltiples niveles: INFO, WARNING, ERROR, SUCCESS, DEBUG, EVENT
   ✓ Timestamps automáticos
   ✓ Formateo con colores en consola
   ✓ Historial de logs (últimos 100)
   ✓ Estadísticas de logs por nivel
   ✓ Logging específico para clicks de botones
   ✓ Logging de inicio/fin de funciones
   
   Métodos principales:
   - Logger.info()       → Información general
   - Logger.warning()    → Advertencias
   - Logger.error()      → Errores
   - Logger.success()    → Acciones exitosas
   - Logger.debug()      → Debugging
   - Logger.event()      → Eventos del sistema
   - Logger.buttonClick()→ Clicks de botones
   - Logger.functionStart() → Inicio de función
   - Logger.functionEnd()   → Fin de función
   
   Razón de implementación:
   - Fundamental para debugging y mantenimiento
   - Permite rastrear el flujo completo de la aplicación
   - Facilita la identificación de problemas
   - El historial permite análisis retrospectivo

2. NAVIGATION.JS - Sistema de Navegación
   ✓ Cambio entre pestañas con validación
   ✓ Gestión de estados activos/inactivos
   ✓ Logging integrado de todas las acciones
   ✓ Scroll automático al inicio al cambiar pestaña
   ✓ Métodos para navegación secuencial (prev/next)
   
   Funcionalidad principal:
   - switchTab(tabName)      → Cambia a pestaña específica (función global)
   - Navigation.showTab()    → Muestra pestaña con validación
   - Navigation.previousTab()→ Pestaña anterior
   - Navigation.nextTab()    → Pestaña siguiente
   - Navigation.getCurrentTab() → Obtiene pestaña actual
   
   Razón de implementación:
   - Centraliza toda la lógica de navegación
   - Validación previene errores al cambiar pestañas
   - Logging permite rastrear el flujo de navegación del usuario
   - Base sólida para futuras mejoras (historial, deep linking, etc.)

3. PARALLAX.JS - Efecto Parallax
   ✓ Efecto parallax en background del header
   ✓ Optimizado con requestAnimationFrame
   ✓ Throttling de eventos para mejor rendimiento
   ✓ Opción de activar/desactivar
   
   Características técnicas:
   - Factor de parallax: 0.5 (background se mueve a mitad de velocidad)
   - Solo activo en el área del header
   - Usa passive event listeners para mejor scroll performance
   
   Razón de implementación:
   - Añade profundidad visual sin sacrificar rendimiento
   - RequestAnimationFrame asegura animaciones fluidas a 60fps
   - Passive listeners permiten que el navegador optimice el scroll

4. UTILS.JS - Utilidades Generales
   ✓ Gestión del botón scroll to top
   ✓ Funciones para localStorage con logging
   ✓ Utilidades de fecha y hora
   ✓ Generación de IDs únicos
   ✓ Validación de email
   ✓ Copiar al portapapeles con fallback
   ✓ Funciones debounce y throttle
   
   Funciones principales:
   - scrollToTop()           → Scroll suave al inicio (función global)
   - saveToStorage()         → Guardar en localStorage
   - loadFromStorage()       → Cargar desde localStorage
   - clearStorage()          → Limpiar localStorage
   - copyToClipboard()       → Copiar texto
   - debounce()             → Limitar frecuencia de llamadas
   - throttle()             → Throttling de funciones
   - generateId()           → IDs únicos
   - formatDate/Time()      → Formateo de fechas
   
   Razón de implementación:
   - Centraliza funciones comunes para reutilización
   - Logging en funciones de storage facilita debugging
   - Debounce y throttle son esenciales para optimización
   - Fallbacks aseguran compatibilidad con navegadores antiguos

DECISIONES TÉCNICAS Y JUSTIFICACIONES
--------------------------------------------------------------------------------

1. HTML5 Puro (Sin Frameworks):
   Razón: Mayor control, menor peso, mejor rendimiento en móviles, sin
   dependencias externas, fácil mantenimiento.

2. Arquitectura Modular:
   Razón: Facilita desarrollo por etapas, mejor organización del código,
   reutilización de componentes, mantenimiento simplificado.

3. Mobile-First CSS:
   Razón: La mayoría de usuarios usarán móviles, mejor rendimiento,
   progressive enhancement, más fácil escalar a desktop que viceversa.

4. Sticky Navigation:
   Razón: Mejora UX al permitir cambio de sección sin scroll, especialmente
   importante en móviles donde el espacio es limitado.

5. Sistema de Logging Robusto:
   Razón: Fundamental para desarrollo, debugging y mantenimiento futuro.
   Pequeña inversión inicial con gran retorno a largo plazo.

6. Scroll Horizontal en Navegación (Móvil):
   Razón: Mejor que menu hamburguesa para 7 pestañas, todas visibles sin
   clicks adicionales, más intuitivo para usuarios.

7. Efecto Parallax con requestAnimationFrame:
   Razón: Animaciones fluidas a 60fps, no bloquea el scroll, mejor que CSS
   parallax para casos complejos, fácil de controlar.

8. LocalStorage para Persistencia:
   Razón: No requiere servidor, funciona offline, suficiente para esta etapa,
   fácil de migrar a solución más robusta después.

MÓDULO BUSCADOR - DOCUMENTACIÓN COMPLETA

ESTADO: IMPLEMENTADO (UI y lógica base) ✓
Fecha de Implementación: 07/02/2025

DESCRIPCIÓN:
--------------------------------------------------------------------------------
El módulo Buscador permite a los usuarios buscar cartas de Yu-Gi-Oh! por nombre
con la opción de aplicar filtros adicionales mediante palabras clave. Es el
primer módulo funcional de la aplicación y sirve como base para la gestión
de cartas.

COMPONENTES PRINCIPALES:
--------------------------------------------------------------------------------

1. BARRA DE BÚSQUEDA PRINCIPAL
   - Input de texto para nombre de carta
   - Botón "Buscar" (icono 🔍)
   - Botón "Limpiar" (icono ✖)
   - Búsqueda al presionar Enter
   
   Razón: Interfaz intuitiva que sigue patrones estándar de búsqueda web

2. FILTROS ADICIONALES
   - Campo de texto para palabras clave
   - Separación por comas
   - Texto de ayuda explicativo
   - Aplicación automática en la búsqueda
   
   Razón: Permite búsquedas más precisas sin sobrecargar la interfaz principal

3. ÁREA DE RESULTADOS
   - Grid responsive de cartas
   - Imagen, nombre y tipo de cada carta
   - Hover effects para interactividad
   - Estados: loading, sin resultados, resultados
   
   Razón: Presentación visual clara y atractiva de los resultados

FUNCIONALIDADES IMPLEMENTADAS:
--------------------------------------------------------------------------------

✓ Búsqueda por nombre de carta (parcial o completa)
✓ Filtros adicionales por palabras clave
✓ Validación de entrada (no buscar si está vacío)
✓ Estados visuales (loading, sin resultados, error)
✓ Limpiar búsqueda completa
✓ Búsqueda con Enter en ambos inputs
✓ Click en carta para ver detalles (placeholder)
✓ Logging completo de todas las acciones
✓ Responsive en todos los dispositivos
