# 🗂️ Destiny Draw – Reporte Completo del Proyecto
**Versión:** Febrero 2026 (Actualización)
**Base:** Análisis sobre código fuente real (todos los módulos)

===============================================================================

## 1. Descripción General

Destiny Draw es una SPA (Single Page Application) sin servidor para jugadores de Yu-Gi-Oh!. Funciona 100% desde el navegador. Usa localStorage para toda la persistencia y se conecta a la API pública de YGOProDeck para datos de cartas. La arquitectura es modular: cada módulo es un objeto JavaScript global independiente.

La app está organizada en dos áreas principales:
- **Pestañas de contenido principal** (`index.html`): Buscador, Mi Deck, Estadísticas, Simuladores, Meta, Formación, Configuración.
- **Sub-pestañas de Simuladores** (gestionadas por `torneo.js`): Mulligan (Hipergeometría), Torneo, Duelo en Vivo, Experimentación, Zona de Práctica, Winrate.

**Estructura de carpetas relevante:**
- `Modules/` — todos los archivos JavaScript (.js)
- `css/` — todos los archivos de estilos (.css)
- `img/` — imágenes estáticas (logo, etc.)
- `ots/` — archivos de música de fondo (.mp3)
- `index.html` — punto de entrada único

**Orden de carga de scripts** (el orden importa por dependencias):
```
logger.js → navigation.js → parallax.js → utils.js → cardviewer.js → buscador.js →
configmanager.js → specialty-analyzer.js → nomenclature-analyzer.js → stats.js →
deck.js → estadisticas.js → config.js → help.js → winrate.js → duelista.js →
favoritas.js → banlist.js → torneo.js → duelo.js → matchups.js → hipergeometria.js →
engines.js → experimentacion.js → zonapractica.js → welcome.js
```

### `logger.js`
Sistema centralizado de logging para desarrollo. Debe cargarse primero antes que cualquier otro módulo. Expone el objeto global `Logger` con niveles de log: `functionStart`, `functionEnd`, `info`, `success`, `error`, `warning`, `debug`, `event`, `buttonClick`. Todos los demás módulos usan `SafeLogger` (alias seguro que no rompe si Logger no existe).

### `navigation.js`
Controla el sistema de pestañas principales. Muestra/oculta las secciones `<section id="X-content">` y activa/desactiva los botones del nav.

| Función | Descripción |
|---|---|
| `init()` | Registra listeners en todos `.nav-button` y carga pestaña inicial (`buscador`). Usa `requestAnimationFrame` para esperar el DOM |
| `showTab(tabName)` | Oculta todo, muestra la sección indicada, activa botón, notifica a módulos dependientes |
| `previousTab()` / `nextTab()` | Navegación circular entre pestañas |
| `getCurrentTab()` | Devuelve la pestaña activa actual |

**Pestañas disponibles:** `buscador`, `mideck`, `estadisticas`, `simuladores`, `meta`, `formacion`, `config`

**Efectos secundarios de `showTab`:**
- Llama a `Estadisticas.updateFloatingWidgetVisibility(tabName)` para mostrar/ocultar el widget flotante de scores
- Al entrar a `simuladores`: llama a `Torneo.init()`
- Al entrar a `mideck`: llama a `Engines.init()`
- Al salir de `simuladores`: llama a `ZonaPractica._cleanupFloatBtns()`
- Despacha un evento `scroll` para actualizar los botones flotantes de desplazamiento

**⚠️ NOTA IMPORTANTE:** Los botones del nav en `index.html` tienen `onclick="switchTab('...')"` Y también reciben un `addEventListener` desde `navigation.js`. Esto provoca doble disparo de `showTab` en cada clic. El fix correcto es eliminar los `onclick` del HTML y dejar solo los listeners del módulo. El botón Config ya es el modelo correcto (sin `onclick` en el HTML).

**Objeto `Shortcuts`** (incluido en el mismo archivo):
Botón flotante `⚡` que abre un menú de accesos rápidos configurables.

| Función | Descripción |
|---|---|
| `init()` | Crea el botón flotante `#shortcuts-float-btn` |
| `openMenu()` | Lee shortcuts desde `ConfigManager.getShortcuts()` y renderiza el panel modal |
| `closeMenu()` | Elimina el overlay |
| `go(index)` | Navega a la pestaña y sección indicadas, refresca el módulo si corresponde |

**Catálogo completo de shortcuts disponibles:** Buscador, Decks Guardados, Mi Deck – Notas, Análisis vs Meta, Internal Score, Winrate, Top Tier, Decks del Meta, Poder de Cartas, Counter-Cards, Exportar Datos, Nivel Duelista, Roles, Mecánicas y Counters, Staples, Nomenclatura, Pilares.

### `stats.js`
Motor de cálculo de puntuaciones. No tiene UI propia — provee los números a `estadisticas.js` y `deck.js`. Expone el objeto global `Stats`.

| Función | Descripción |
|---|---|
| `calculateInternalScore(cards)` | Calcula Consistencia, Potencia, Resiliencia (0–10) por roles asignados |
| `calculateExternalScore(cards, powerCache)` | Vulnerabilidad del deck vs cartas del meta que counteren sus mecánicas |
| `calculateCounterDeckScore(cards)` | Capacidad de interrupción del deck al meta, con penalización por bricks |
| `calculateDiminishingReturns(roleName, count)` | Penaliza sobrecargar un rol según umbrales del Config |
| `calculateRPSModifier(pillarA, pillarB)` | Devuelve el modificador RPS entre dos pilares dominantes |

**Detalles de `calculateInternalScore`:**
- Normaliza variantes de nombre de rol a forma canónica
- Pilares: Consistencia (searcher, starter), Potencia (boss monster, boardbreaker, booster, removal, disruption), Resiliencia (negator, extender, recycle, undestroyable, untargetable, unaffectable)
- Cartas con restricción "once per turn" o "per duel": copias adicionales cuentan al 50%
- Penalización por deck > 43 cartas: -0.5 por cada carta extra
- Cada pilar se escala (×15 consistencia, ×20 potencia, ×18 resiliencia) y se limita a 10
- Ponderación final: 33% cada pilar
- Los pesos de cada rol (0.1–1.0 definidos en ConfigManager) multiplican el aporte al pilar

### `estadisticas.js`
Módulo de visualización del análisis completo. Es el módulo más extenso de la app. Expone el objeto global `Estadisticas`.

**Estado interno:**
- `metaDecks` — decks del meta cargados desde localStorage
- `metaFolders` — lista de carpetas de meta ordenadas cronológicamente
- `selectedFolders` — filtro multi-carpeta activo (`[]` = Todo el Meta)
- `powerScoreCache` — cache del Power Score calculado
- `metaCardLibrary` — biblioteca de cartas del meta: `{ cardId → { id, name, type, roles } }`
- `metaDeckScores` — scores pre-calculados por deck: `"folder|||deckname" → { internalScore, externalScore, pillars, calculatedAt }`
- `crossScores` — scores cruzados N×N entre decks del meta
- `topTierFilter` — filtro activo del Top Tier (`'powercreep'` | `'consistency'` | `'power'` | `'resilience'`)
- `topTierPCMode` — modo del Power Creep (`'internal'` | `'external'`)

**Secciones que renderiza:**

| Sección (ID) | Contenido |
|---|---|
| `deck-analysis-sec` | Análisis vs Meta: Internal/External/Counter-Deck Score, mecánicas detectadas, cartas amenaza, decks amenazantes, staples faltantes |
| `deck-stats-sec` | Internal Score con barras por pilar |
| `top-tier-sec` | Top Tier con filtros por pilar y modo Power Creep |
| `meta-decks-sec` | Lista de decks del meta con filtro multi-carpeta |
| `power-scores-sec` | Power Score de cada carta del meta |

## 4. Dependencias Externas
