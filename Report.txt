## 5. FLUJOS CRÍTICOS

### 5.1 Cambio de pestaña
```
switchTab(name) → Navigation.showTab(name)
  → oculta todos .tab-content, activa #name-content
  → Estadisticas.updateFloatingWidgetVisibility(tabName)
  → si simuladores:       Torneo.init()
  → si mideck:             Engines.init()
  → si saliendo de simuladores: ZonaPractica._cleanupFloatBtns()
  → si meta:               Meta.init()
  → si formacion:          Formacion.init()
  → window.scrollTo({ top:0, behavior:'smooth' })
  → ContentManager.applyAll()
```

### 5.2 Agregar carta al deck (desde Buscador)
```
Buscador.addCard(index)
  → Deck.syncFromViewer(card.id, card, currentQty + 1)
  → si carta nueva: autoAssignRoles() + SpecialtyAnalyzer + NomenclatureAnalyzer
  → Deck.render()  → recalcula Internal Score en tiempo real
    (Stats.calculateInternalScore — el G1/G2 Score NO se recalcula aquí, ver 7.2)
  → External Score se recalcula si powerScoreCache existe
```

### 5.3 Importar .ydk a Mi Deck
```
Deck.importYDK()
  → input[file] .ydk → parseYDK(content, filename)
  → overlay de carga "Importando deck... N cartas"
  → fetch API YGOProDeck (batch por IDs únicos)
  → construye newCards con autoAssignRoles()
  → Deck.cards = newCards; Deck.render(); Deck.onDeckLoaded()
  → elimina overlay → alert "Deck importado"
```

### 5.4 Cálculo de scores — ciclo completo
```
Stats.calculateInternalScore(Deck.cards)
  → loop de roles → rendimientos decrecientes por pilar (consistency/power/resilience)
  → devuelve { internalScore, consistency, power, resilience,
               totalCards, mainCards, penalty }
  → (el campo g1Score/g2Score que versiones previas de este reporte mencionaban
     NO existe en el objeto devuelto actualmente — ver nota 7.2)

Stats.calculateExternalScore(Deck.cards, powerScoreCache, metaDecks)
  → cruza specialties del deck con powerScoreCache
  → RPS modifier (ignorando loser='ninguno')
  → devuelve { externalScore, g1Vulnerability, g2Vulnerability, ... }
```

### 5.5 Actualizar Scores del Meta — flujo automático completo (async)
```
Estadisticas.recalculateAllMetaDeckScores()  ← async
  → lista todos los decks con secciones (sin importar si fueron abiertos antes)
  → crea overlay #meta-update-overlay con spinner + barra de progreso + nombre del deck actual

  FASE 1 (0–60%) Enriquecimiento automático:
    por cada deck en la lista:
      → IDs no presentes en metaCardLibrary → fetch API en batches de 10
      → autoAssignRoles() + SpecialtyAnalyzer para cada carta nueva
    → _saveMetaCardLibrary()

  FASE 2 (60–92%) Cálculo de scores:
    por cada deck:
      → _computeAndSaveMetaDeckScore(folder, filename)
      → Internal Score + pilares con fakeCards desde la librería

  FASE 3 (92–100%) Cross-Score N×N:
    → calculateCrossExternalScores()
    → metaDeckScores[key].externalScore = crossExternalScore
    → guarda yugioh_cross_scores + yugioh_meta_deck_scores

  → "¡Listo! N decks actualizados" 700ms → overlay desaparece → render()
```
Ya no es necesario abrir cada deck manualmente. Un solo clic procesa todos.

### 5.6 Selección de perfil
```
Welcome.enter(tabName, levelKey)
  → ContentManager.applyProfile(levelKey)  → 'dd_player_profile'
  → ConfigManager.savePlayerLevel(levelKey) → 'yugioh_player_level'
  → MusicPlayer.setTrack(cfg.tracks[levelKey])
  → Welcome.dismiss() → 'dd_welcome_dismissed' = 'true'
  → Navigation.showTab(tabName)
```

### 5.7 Borrar Todo / Restaurar Config
```
Config.borrarTodo()
  → localStorage.clear() + _resetModulesInMemory() + Welcome.init()

Config.resetToDefault()  ← parcheado por DefaultData
  → localStorage.clear() + await DefaultData.init()
```

### 5.8 DefaultData.init() — inyección única por tipo
```
window.load → DefaultData.init()
  → _initNotes / _initSpecialties / _initGames / _initMasters
  → _initDecks / _initStaples / _initEngines / _initGenesys  (fetch API)
  → _patchConfig() → sobreescribe Config.resetToDefault
```

## 7. SISTEMA DE SCORING — DETALLE

### 7.1 Internal Score
`Stats.calculateInternalScore(cards)`. Loop de roles con rendimientos decrecientes.
Devuelve `{internalScore, consistency, power, resilience, totalCards, mainCards, penalty}`.

### 7.2 G1/G2 Score — ⚠️ DISEÑO GUARDADO, CÁLCULO NO CONECTADO

**Estado real verificado en el código (Jul 2026): esta funcionalidad está a medias.**

Lo que SÍ existe y funciona:
- Estructuras de config en `data.js`: `g1g2Roles`, `roleBasePower`, `reliabilityTable`, `scoringLayers`, con sus getters (`getG1G2Roles`, `getRoleBasePower`, `getReliability`, `getScoringLayers`).
- Panel de Config completo en `formacion.js` ("Scoring Avanzado (G1/G2)") con los 7 métodos save de la sección 7.6, que sí leen/escriben `yugioh_config` correctamente.
- Clases CSS en `style_simuladores.css` (`.analysis-g1g2-row`, `.analysis-g1g2-item`, `.analysis-g1g2-label`, `.analysis-g1g2-val`, `.analysis-g1g2-detail`, `.analysis-g1g2-profile`) — **pero ninguna de estas clases aparece referenciada en ningún archivo `.js`**, es decir, CSS huérfano a la espera de un renderer.

Lo que NO existe actualmente:
- No hay ninguna función que calcule `g1Score` / `g2Score` en todo el proyecto (búsqueda exhaustiva: 0 coincidencias).
- `Stats.calculateInternalScore()` NO devuelve `g1Score` ni `g2Score`.
- `Deck.render()` NO recalcula ningún G1/G2 Score en tiempo real.
- La fórmula descrita más abajo (BasePower × L1 × L2 × L4 × L5 × Reliability) representa el **diseño previsto**, no una fórmula implementada — no hay ningún lugar del código que la ejecute.
- `segmentDescription()` (NomenclatureAnalyzer, `data.js:2208`) está definida pero no se invoca desde ningún otro punto del código; es la pieza que debería alimentar las capas L1/L2/L4/L5 y actualmente no está conectada.

**Fórmula prevista (pendiente de implementar):**
```
CardScore = BasePower(L3) × L1_mult × L2_mult × L4_mult × L5_mult × Reliability

L1 — Velocidad:   keywords en 'condicionActivacion'
L2 — Coste:       keywords en 'costoActivacion'
L4 — Restricción: keywords en 'restriccion'
L5 — Alcance:     keywords en 'efectoGenerico'
Reliability: tabla por copias (1→0.40, 2→0.65, 3→0.85, 4→0.90, 5→0.95)
             + pool indirecto de searchers del mismo arquetipo

g1g2Roles[dominantRole] === 'g1' → g1Score
g1g2Roles[dominantRole] === 'g2' → g2Score
'neutral'                        → 50/50
```
**Antes de trabajar en esta área:** confirma con el usuario si el objetivo es (a) terminar de conectar el cálculo con la config ya guardada, o (b) el panel de Config quedó adelantado a propósito y el cálculo vendrá después. No asumas que ya funciona.

### 7.3 External Score (deck activo)
`Stats.calculateExternalScore()` — deck vs powerScoreCache.
RPS modifier ignorando loser='ninguno'.
Devuelve `{externalScore, g1Vulnerability, g2Vulnerability, ...}`.

### 7.4 External Score (meta) = Cross-Score N×N
`calculateCrossExternalScores()`. Para cada deck A: amenazas de counters de B ponderadas por internalScore de B y RPS. `crossExternalScore = (1 - threat/baseline) × 10`.

### 7.5 RPS
Reglas `[ganador, perdedor]`. `perdedor='ninguno'` → ese pilar no tiene counter. Modificadores: ×1.25 ventaja / ×0.75 desventaja / ×1.0 neutral.

### 7.6 Scoring Avanzado — métodos save en Config

## 8. SISTEMA DE ROLES Y NOMENCLATURA — GESTIÓN EN CONFIG

### 8.1 Detección de roles
```
autoAssignRoles(card) → detectPossibleRoles(card)
  por cada rol en roleConditions:
    keywords coinciden en desc
    AND conditionals (si hay) también coinciden
    AND notContains (si hay) NO coinciden
    → rol asignado

roleConditions[roleName]: { keywords:[], conditionals:[], notContains:[] }
```

### 8.2 Pattern de renombrado con input oculto (roles y nomenclatura)
El badge de nombre es siempre el elemento visible. El input se oculta con `display:none`.

| Elemento | Roles | Nomenclatura |
|---------|-------|-------------|
| Span visible | `id="rpn-${roleName}"` | `id="npn-${cat.id}"` |
| Input oculto | `id="rni-${roleName}"` | `id="nni-${cat.id}"` |
| Botón lápiz | `focusRenameInput(roleName)` | `focusNomRenameInput(catId)` |
| onblur | `renameRole(el)` | `renameNomCategory(catId, el)` |
| Clonar | `duplicateRole(roleName)` → `ConfigManager.duplicateRole` | `duplicateNomCategory(catId)` → `ConfigManager.duplicateNomenclatureCategory` |
| Borrar | `deleteRole(roleName)` | `deleteNomCategory(catId)` |

`duplicateNomenclatureCategory(catId)` — deep-copy de la categoría, nuevo ID `custom_` + timestamp, nombre + " (copia)", insertada inmediatamente después de la original. Devuelve el nuevo ID para scroll.

## 12. NOTAS PARA TRABAJAR EFICIENTEMENTE

**Para cambios puntuales:** sube solo la función afectada indicando objeto y método.

**Para CSS:** todos los ajustes responsive van exclusivamente en `responsive_style.css`.

**Archivos que NO necesitas subir salvo cambios:**
- `html2canvas_min.js` — librería externa
- `logger.js` — solo si cambia `TARGETS` o formato del reporte

**Variables CSS globales** (en `style_core.css`):
`--gold-color` · `--accent-color` · `--bg-card` · `--text-light` · `--danger-color` · `--spacing-sm/md/lg`

**Renombrados respecto a versiones anteriores:**
- `Duelo` → `DueloEnVivo` (simuladores.js)
- `dd_power_scores_cache` → `yugioh_power_cache`
- `Stats` vive dentro de `data.js`
- `default_data.js` carga DESPUÉS de `formacion.js` y ANTES de `logger.js`

**Diferencia clave entre los dos External Scores:**
- Deck activo → `Stats.calculateExternalScore()` → deck vs powerScoreCache
- Decks del meta → `calculateCrossExternalScores()` → N×N real

**Diferencia clave entre Peso de Rol y Poder Base:**
- `roleWeights` → escala 0.1–2.0 → Internal Score clásico (rendimientos decrecientes) — ACTIVO
- `roleBasePower` → escala 0–10 → pensado para G1/G2 Score — guardado en config, aún sin consumidor (ver 7.2)

**Pendiente conocido (no es bug, es feature a medio construir):**
- El sistema G1/G2 Score (config + UI completos) no tiene motor de cálculo conectado.
  Ver detalle completo en la sección 7.2 antes de asumir que "ya existe".

**Regla de oro para añadir una sección a Config:**
1. Añadir el bloque HTML en `Config.render()` con el ID de sección
2. Definir `renderXxxSection()` que devuelve el HTML interno
3. Definir los métodos save que llaman `ConfigManager.getConfig()` / `saveConfig(cfg)`
4. Si hay datos nuevos en `defaultConfig`, añadir los getters correspondientes en `ConfigManager`
Si se omite el paso 2, `Config.render()` lanza un TypeError silencioso y la pestaña queda en blanco.
