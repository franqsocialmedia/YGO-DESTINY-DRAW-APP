RESUMEN EJECUTIVO
--------------------------------------------------------------------------------
Se ha implementado exitosamente el sistema de Roles Compuestos con
Condicionales. Este sistema permite:

1. Definir roles que requieren condicionales (palabras que DEBEN estar)
2. Definir keywords (AL MENOS UNA debe estar presente)
3. Combinar ambos para detección precisa de roles
4. Gestionar condicionales desde Configuración
5. Compatibilidad con roles simples (sin condicionales)
6. Diferenciación visual clara en UI

================================================================================
CONCEPTO - ROLES COMPUESTOS
================================================================================

ROLES SIMPLES (Paso 1):
- Solo verifica que AL MENOS UNA keyword esté presente
- Ejemplo: "Searcher" → ["add", "from your deck"]
- Si encuentra "add" → asigna rol Searcher

ROLES COMPUESTOS (Paso 3):
- Verifica que TODAS las condicionales estén presentes
- Y que AL MENOS UNA keyword esté presente
- Ejemplo: "Handtrap" → 
  • Condicionales: ["quick-effect"] (DEBE estar)
  • Keywords: ["from your hand", "from the hand"] (AL MENOS UNA)
- Si tiene "quick-effect" Y "from your hand" → asigna rol Handtrap

BENEFICIO:
- Mayor precisión en detección de roles
- Evita falsos positivos
- Permite roles más específicos y complejos

ESTRUCTURA DE DATOS - roleConditions
--------------------------------------------------------------------------------

ConfigManager.defaultConfig.roleConditions:
{
  "NombreRol": {
    conditionals: ["palabra1", "palabra2"],  // TODAS deben cumplirse
    keywords: ["keyword1", "keyword2"]       // AL MENOS UNA debe cumplirse
  }
}

ROLES COMPUESTOS PREDEFINIDOS:

1. Handtrap
   - Condicionales: [] (vacío = sin condicionales, es rol simple)
   - Keywords: ["from your hand", "from the hand", "from their hand"]
   - Lógica: Si tiene alguna keyword → es Handtrap

2. Disruption
   - Condicionales: ["quick-effect", "during either player"]
   - Keywords: ["negate", "destroy"]
   - Lógica: Si tiene "quick-effect" Y "during either player" Y ("negate" O "destroy") → es Disruption

EJEMPLO PRÁCTICO:

Carta: "Effect Veiler"
Descripción: "During your opponent's Main Phase (Quick Effect): You can send this card from your hand to the Graveyard, then target 1 Effect Monster your opponent controls; negate that face-up monster's effects until the end of this turn."

Análisis:
- ✅ Tiene "quick effect" (condicional de Disruption)
- ✅ Tiene "during" (condicional de Disruption)
- ❌ NO tiene "either player" (falta condicional)
- ✅ Tiene "negate" (keyword de Disruption)
- ✅ Tiene "from your hand" (keyword de Handtrap)

Resultado:
- ✅ Asigna "Handtrap" (cumple keywords, no tiene condicionales)
- ❌ NO asigna "Disruption" (falta condicional "either player")

1. DECK.JS - autoAssignRoles()
--------------------------------------------------------------------------------

LÓGICA ACTUALIZADA:

Para cada rol:
1. Verificar si existe en roleConditions
2. Si existe en roleConditions:
   a) Verificar que TODAS las condicionales estén en desc
   b) Si todas las condicionales se cumplen:
      - Verificar que AL MENOS UNA keyword esté en desc
      - Si se cumple → asignar rol
3. Si NO existe en roleConditions:
   - Usar lógica simple (buscar keywords en roles)
   - Si encuentra alguna → asignar rol

PSEUDOCÓDIGO:
```javascript
for each (roleName, keywords) in roles {
  if (roleConditions[roleName]) {
    // ROL COMPUESTO
    allConditionsMet = true
    for each conditional in roleConditions[roleName].conditionals {
      if (!desc.includes(conditional)) {
        allConditionsMet = false
        break
      }
    }
    
    if (allConditionsMet) {
      for each keyword in roleConditions[roleName].keywords {
        if (desc.includes(keyword)) {
          assignRole(roleName)
          break
        }
      }
    }
  } else {
    // ROL SIMPLE
    for each keyword in keywords {
      if (desc.includes(keyword)) {
        assignRole(roleName)
        break
      }
    }
  }
}
```

VENTAJAS:
- Compatible con roles simples (sin romper nada)
- Permite roles complejos y precisos
- Escalable y mantenible

GESTIÓN DESDE CONFIGURACIÓN
================================================================================

USUARIO PUEDE:

1. VER CONDICIONALES Y KEYWORDS
   - Expandir rol en Config → Roles y Palabras Asociadas
   - Ver sección "Roles Compuestos (Opcional)"
   - Chips rojos = condicionales
   - Chips azules = keywords de condición

2. AGREGAR CONDICIONALES
   - Input en sección condicionales
   - Escribir condicional (ej: "quick-effect")
   - Enter o botón "Agregar Condicional"
   - Se normaliza a lowercase automáticamente

3. ELIMINAR CONDICIONALES
   - Click × en chip rojo
   - Se elimina con confirmación

4. AGREGAR KEYWORDS DE CONDICIÓN
   - Input en sección keywords
   - Escribir keyword (ej: "negate")
   - Enter o botón "Agregar Keyword"
   - Se normaliza a lowercase

5. ELIMINAR KEYWORDS DE CONDICIÓN
   - Click × en chip azul
   - Se elimina con confirmación

6. CONVERTIR ROL SIMPLE EN COMPUESTO
   - Rol sin condicionales = rol simple
   - Agregar condicional → se convierte en compuesto
   - Agregar keywords de condición

7. CONVERTIR ROL COMPUESTO EN SIMPLE
   - Eliminar todas las condicionales
   - Rol vuelve a ser simple
   - Solo usa keywords normales

EJEMPLO PRÁCTICO:

Usuario quiere crear "Quick Hand Trap":

1. Config → Roles y Palabras Asociadas
2. Crear nuevo rol: "Quick Hand Trap"
3. Palabras clave normales: (vacío o ignoradas)
4. Sección Roles Compuestos:
   - Condicional: "quick-effect"
   - Keyword: "from your hand"
5. Guardar

Ahora cartas con "quick-effect" Y "from your hand" tendrán rol "Quick Hand Trap"

================================================================================
LIMITACIONES Y CONSIDERACIONES
================================================================================

LIMITACIONES:
- Condicionales y keywords son case-insensitive
- No soporta regex (solo includes)
- Todas las condicionales son AND, no OR

CONSIDERACIONES:
- Más condicionales = más específico pero menos cartas
- Balance entre precisión y cobertura
- Probar con cartas reales antes de usar

RECOMENDACIONES:
- Empezar con roles simples
- Convertir a compuestos solo si necesario
- Usar condicionales para roles muy específicos
- Mantener keywords de condición cortas y claras

```json

    "Handtrap": {
      "conditionals": [],  // Sin condicionales = usa keywords de aquí
      "keywords": ["from your hand", "from the hand"]
    }
  }
}
```
